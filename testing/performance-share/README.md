# Share transfer measurement

This controller measures the production `LocalShareService` path from encrypted
local SQLite to an existing disposable AWS deployment. Its source execution and
portable snapshot are explicit fixtures. It creates the source Agent, Session,
hosted environment and template through real services, completes one synthetic
Turn, then runs real ZIP creation, chunk uploads, destination admission/staging,
source release, and destination activation. It does not invoke a model or launch
a source native VM.

After sourcing the disposable deployment's `runtime.env`:

```sh
AWS_E2E=true AWS_E2E_SHARED_SESSIONS=true AWS_E2E_REAL_CODEX=true \
  node --import tsx testing/performance-share/controller.ts \
  --output /absolute/path/share-performance.json
```

The shared API URL must be the deployment's `/v1` Lambda endpoint. Existing AWS
controller prerequisites apply: region, Cognito fixture, admitted model ID,
shared API URL, and IAM operator API URL. No credential values are persisted in
the result. The real-Codex opt-in remains required because this uses the deployed
execution-capable application; no inference is intentionally submitted here.

The default sizes are 1, 10, and 40 MiB. Each cell has a separate source Session
and destination space. `--sizes-mib 1,40` selects a subset. Random high-entropy
bytes and their expected hash are generated **before** the transfer timer, so
compression cannot turn a large fixture into a tiny zero-filled upload.
`--timeout-ms` bounds transfer observation, defaulting to 600000 and capped at
900000. A completion observed beyond that deadline remains failed with its late
duration recorded. Failed and unstarted matrix cells remain in the artifact.

`--deployment-revision FULL_SHA` records caller-supplied deployment provenance.
The controller records its own Git revision/dirty state and UTC cell boundaries
including cleanup. Verify deployed bundle hashes separately.

## Measurement boundaries

The monotonic total begins immediately before `LocalShareService.create` and
ends when polling first observes `complete`. It includes the real archive,
encrypted local persistence, HTTP uploads, stage, source release, and activation.
Polling adds at most its nominal 25 ms interval plus event-loop scheduling;
artifact recording and transport observation add small harness overhead. Setup,
payload generation, verification and cleanup have separate phases.

The production `share-transfer` performance record is captured as safe numeric
metrics. Its snapshot duration covers the in-memory fixture callback, not a
native workspace export. Archive/compression work appears in quiesce and total
duration. Upload duration is summed across chunks; request spans separately
record status, timing, and payload bytes. Upload payload bytes exclude multipart
framing; JSON payload bytes include its serialization. These are not TLS wire
bytes, storage billing units, or billed Lambda duration. Warm/cold is unclassified.

Verification occurs after the transfer timer:

- The hosted Session ID, Agent configuration, completed Turns and public Item
  history match the source. Further source input is rejected after release, and
  the deterministic source executor reports closed.
- By default, every uploaded archive part is downloaded through the real Files
  API, checked against the stage manifest, concatenated and checked against the
  archive hash. The ZIP is then decoded locally and its payload checked against
  the independently generated bytes' digest. `--verify-download false` skips
  only this optional download verification and records that limit.

An activated Share is not evidence that a destination guest extracted the archive
or produced a new model Turn. This controller makes no claim about native export,
guest startup, destination execution readiness, model latency, signed desktop
distribution, or native UI behavior. The separate live Share correctness proof
covers hosted continuation. The source fence here is a service-level observation,
not a process census or crash-race proof.

## Evidence and cleanup

Safe JSON snapshots are written atomically at setup/status/request boundaries
and after cleanup. They retain failed status, failure phase, incomplete durations,
HTTP statuses, payload/archive sizes, fixture IDs, digests and cleanup outcomes.
Raw prompts, replies, tokens, Share release proofs, and response-error bodies are
not exported. Private source SQLite stores are temporary and removed after the
Share service stops; an uncertain stop retains the directory and fails cleanup.

Failure cleanup attempts an abort while Share remains abortable, then stops the
coordinator. It attempts destination Session and Agent deletion independently,
deletes uploaded Files only after destination Session retirement is confirmed,
and removes all disposable Cognito users. Per-file cleanup outcomes remain in
the artifact. An upload whose acknowledgement is lost may leave an unknown File
ID; uploaded-file cleanup then remains unconfirmed even if all known IDs were
deleted. Destination Share records and spaces still belong to deployment
teardown, which the deployment owner performs. Source and cloud cleanup failures
remain failures even if the transfer measurement succeeded.

```sh
npx vitest run tests/performance-share --no-file-parallelism
npm run typecheck
```

Focused tests use real local services and a mocked destination transport. They
verify accounting, exact archive bytes and cleanup behavior; their durations are
not real AWS performance results.
