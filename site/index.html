The narrow journey

Connect. Explain. Run.

Every consumer follows the same path. Rat Things discovers what is installed, verifies each provider account, resolves permissions before execution, and retains evidence after the run.

Once this narrow journey is delightful and stable, expand it.

  1. 01

    Discover and connect

    rat-things doctor
rat-things plugins
rat-things connect slack \
  --credential-file support.json \
  --access read-only
  2. 02

    Define and explain

    rat-things thing-create \
  --file thing.json
rat-things thing-explain \
  "$THING_ID"
  3. 03

    Run and observe

    rat-things thing-run "$THING_ID" \
  --idempotency-key first-safe-test
rat-things watch "$RUN_ID" --follow

The host installs the deployment and brings identity and OAuth. The consumer renders manifests and preserves opaque IDs. Rat Things remains authoritative for ownership, provider verification, permissions, and run state.

01

Multiple accounts

Verify first. Label once.

rat-things connect slack \
  --credential-file support.json \
  --access read-only --alias support

rat-things connect slack \
  --credential-file ops.json \
  --access read-write --alias operations

The integration verifies each credential, derives its provider identity and authority, then stores it outside Thing and run state.

02

Create and share

Return the actual file.

rat-things --thread pelican-demo \
  --sandbox workspace-write \
  "Create an image of a pelican riding a bicycle.
  Save it under .rat-things/artifacts/."

rat-things files --thread pelican-demo

  --thread pelican-demo

The final command prints a fresh private URL. Publish a directory or MP4 with publish site or publish video; the retained source remains durable with the thread.

What happens after enter

Disposable compute.
Durable work.

A webhook and the CLI differ only at ingress. Rat Things authenticates the caller, commits work before compute, fences one session owner, and preserves state before returning a result.

  1. 01Receive

    Verify IAM or a provider signature and derive the owner.

  2. 02Remember

    Commit the prompt and mailbox entry before scheduling.

  3. 03Fence

    Give one MicroVM ownership of the thread and filesystem.

  4. 04Run

    Launch or resume Codex with its tools and durable workspace.

  5. 05Return

    Publish files, checkpoint state, suspend, and deliver.
