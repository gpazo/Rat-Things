Four small demos.
The whole product.

People can stay prompt-first. Agents and CI can opt into stable identity, structured output, asynchronous submission, explicit policy, and fresh file URLs.

01

Continue a thread

Ask. Then keep going.

rat-things --thread release \
  "Inspect the failing build"

rat-things --thread release \
  "Fix it and rerun the tests"

The name reuses the Codex thread, workspace, and published files—even after replacement compute.

02

Create and share

Return the actual file.

rat-things --thread pelican-demo \
  --sandbox workspace-write \
  "Create an image of a pelican riding a bicycle.
  Save it under .rat-things/artifacts/."

rat-things files --thread pelican-demo
rat-things file pelican-bicycle.webp \
  --thread pelican-demo

The final command prints a fresh private URL. The default lifetime is 24 hours; the underlying file remains durable with the thread.

03

Automate safely

Make retries boring.

rat-things chat \
  --thread release \
  --idempotency-key "$TURN_ID" \
  --sandbox workspace-write \
  --json --no-wait \
  "Continue the task"

Progress stays on stderr. JSON receipts stay on stdout. Polling, timeout, model, and reasoning controls are available with help --all.

What happens after enter

Disposable compute.
Durable work.

A webhook and the CLI differ only at ingress. Rat Things authenticates the caller, commits work before compute, fences one session owner, and preserves state before returning a result.

  1. 01Receive

    Verify IAM or a provider signature and derive the owner.

  2. 02Remember

    Commit the prompt and mailbox entry before scheduling.

  3. 03Fence

    Give one MicroVM ownership of the thread and filesystem.

  4. 04Run

    Launch or resume Codex with its tools and durable workspace.

  5. 05Return

    Publish files, checkpoint state, suspend, and deliver.

Resume means resume

The machine can disappear.
The work does not.

A thread is larger than a chat transcript. Rat Things stores the mailbox, Codex app-server state, workspace, and published file catalog outside the MicroVM, under a fenced owner lease.

Engineering preview

Isolation is a boundary, not a permission slip.

Treat prompts, repositories, model output, generated files, and webhook fields as untrusted. Production still requires an independent IAM and malicious-repository review, budgets, outbound policy, output redaction, destination authorization, and sustained-load testing.
